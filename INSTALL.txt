NEW DIAL PAGE -- WIRING PACKAGE (step 15)
=========================================
Unzip INTO your project folder (D:\myProjects\panchang-clock-structure\panchang-clock) so that
ui/, engine/, config/, tests/ and data/ merge with the existing folders.  It REPLACES
ui/main_window_hi.py (the only existing file it touches) -- keep a copy of the old one first.

BUTTONS NOW
  button 1  Home      = the dial page            (GPIO17, as before)
  button 2  Calendar  = the calendar page        (GPIO27, was "Panchang")
  button 3  Setup     = Wi-Fi + location setup   (GPIO22, was "Calendar")
  button 4  unused                               (GPIO23, was "Wi-Fi setup")
  No rewiring.  Safe shutdown: hold button 2 + button 3 for 3 s (as before).
  The Panchang page and the old Home page are no longer imported (files stay, unused).
  Idle return: on the Calendar page with no button press for idle_return_seconds
  (settings.yaml, default 300 = 5 min) the clock returns to Home.

CITY NAME ON THE CLOCK
  The name typed on the setup page is looked up in config/cities_hi.yaml:
   - a misspelling is tolerated (Muzzafarnagar, Muzaffar Nagar, Muzafarnagr ...)
   - the match must be within 60 km of the clock's coordinates, so a typo can never
     pick a far-away city (Muzaffarpur stays "Muzaffarpur")
   - a name that is not in the table is shown exactly as typed (English)
   - a name already in Devanagari is shown as typed
  Try it:   python ui/city_names_hi.py

TEST ON THE PC FIRST (activate the venv first:  .\venv\Scripts\Activate.ps1)
  python ui/page_vedic_dial_hi.py          live page, real engine, no GPIO needed
  python ui/dial_preview.py                sample data
  python tests/test_festival_vyapti.py --selftest
THEN: git add . / commit / push, and on the Pi: git pull, sudo reboot.

IF A VALUE STAYS "..." OR LOOKS WRONG: the page prints the error and keeps running --
read it in the PC terminal, or on the Pi:  tail -n 40 /dev/shm/vedicghadi.log
